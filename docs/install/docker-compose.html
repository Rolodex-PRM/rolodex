Install

Docker Compose

Recommended for production. Two containers — Postgres and Rolodex — share one published HTTP port for the website, API, CardDAV, and CalDAV.

Prefer a shorter path? Quick start is the same install with fewer choices.

Step 1 — Download the required files

Create a directory for the compose file and environment file:

mkdir ./rolodex-app
cd ./rolodex-app

Fetch the current files from main:

curl -fsSL -o docker-compose.yml https://raw.githubusercontent.com/Rolodex-PRM/rolodex/main/docker-compose.yml
curl -fsSL -o .env https://raw.githubusercontent.com/Rolodex-PRM/rolodex/main/.env.example

Or clone the repository and copy .env.example to .env. Keep both files in the same directory so Compose can find them.

Step 2 — Populate the .env file

Edit .env before the first start on a shared host:

  • Set ROLODEX_IMAGE to gallinij/rolodex:latest, or pin a release tag such as gallinij/rolodex:0.1.0.
  • Replace POSTGRES_PASSWORD. Prefer letters and numbers so Compose parsing stays simple.
  • Replace CREDENTIALS_KEY with a fresh 32-byte base64 value: node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
  • Change PORT only if 8080 is already taken on the host.
  • Set PUBLIC_URL only when phones should use a different origin than the browser (for example a Cloudflare tunnel hostname).

Every variable is documented on Environment variables.

Step 3 — Start the containers

docker compose pull
docker compose up -d

Wait until both services are healthy, then open http://localhost:8080 (or your host and port). The first registration becomes the administrator.

To build from this repository instead of pulling Hub: docker compose up -d --build.

Compose file

The published file is the source of truth in the repository. Compose pulls ${ROLODEX_IMAGE:-gallinij/rolodex:latest}, mounts an uploads volume at /data, and keeps Postgres on 127.0.0.1 for local backups. 

name: rolodex

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-rolodex}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-rolodex}
      POSTGRES_DB: ${POSTGRES_DB:-rolodex}
    ports:
      - "127.0.0.1:${POSTGRES_PORT:-5472}:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER -d $$POSTGRES_DB"]
      interval: 5s
      timeout: 5s
      retries: 20

  rolodex:
    image: ${ROLODEX_IMAGE:-gallinij/rolodex:latest}
    build: .
    restart: unless-stopped
    env_file: .env
    environment:
      DATABASE_URL: postgres://${POSTGRES_USER:-rolodex}:${POSTGRES_PASSWORD:-rolodex}@postgres:5432/${POSTGRES_DB:-rolodex}
      S3_ENDPOINT: ${DOCKER_S3_ENDPOINT:-}
      DATA_DIR: /data
      BACKUP_DIR: /backups
      API_PORT: 3000
      CARDDAV_PORT: 3001
      DOCKER_SITE: "true"
      CARDDAV_BEHIND_PROXY: "true"
    ports:
      - "${PORT:-8080}:8080"
    volumes:
      - uploads:/data
      - ${BACKUP_DIR:-./backups}:/backups
    depends_on:
      postgres:
        condition: service_healthy

volumes:
  postgres-data:
  uploads:
ROLODEX_IMAGE=gallinij/rolodex:latest
PORT=8080
POSTGRES_USER=rolodex
POSTGRES_PASSWORD=replace-me
POSTGRES_DB=rolodex
CREDENTIALS_KEY=replace-with-32-byte-base64
# PUBLIC_URL=https://rolodex.example.com

Upgrade

  1. Back up Postgres and the uploads volume (see the README backup scripts).
  2. Bump ROLODEX_IMAGE to the new tag, or keep :latest.
  3. Run docker compose pull then docker compose up -d.

A GitHub Release publishes the matching Hub tags. A push to main alone does not publish an image.

Notes

  • Use docker compose (v2 plugin), not the old docker-compose binary.
  • Uploaded files live in the uploads volume unless you set DOCKER_S3_ENDPOINT.
  • If the Postgres volume already exists, change POSTGRES_PASSWORD in .env and inside Postgres together.
  • Put TLS on a reverse proxy or tunnel in front of PORT. Rolodex itself speaks HTTP.
  • Back up with ./scripts/backup.sh and verify with ./scripts/verify-backup.sh. See the backup guide.
