Backup & recovery

Migration guide

Move Rolodex to a new server or NAS. Backups are portable: they do not depend on the old Docker volume IDs or absolute host paths.

Overview

  1. Back up the existing installation and verify the backup.
  2. Install Docker on the new machine.
  3. Copy docker-compose.yml and a new .env (with the same CREDENTIALS_KEY).
  4. Start Compose, restore the backup, adjust URLs and the reverse proxy.
  5. Sign in and confirm people, files, and sync clients.

Steps

On the old machine

./scripts/backup.sh /path/to/portable-backup
./scripts/verify-backup.sh /path/to/portable-backup
# Copy the backup folder and your CREDENTIALS_KEY to secure storage

On the new machine

mkdir ./rolodex-app && cd ./rolodex-app
curl -fsSL -o docker-compose.yml https://raw.githubusercontent.com/Rolodex-PRM/rolodex/main/docker-compose.yml
curl -fsSL -o .env https://raw.githubusercontent.com/Rolodex-PRM/rolodex/main/.env.example
# Edit .env: set POSTGRES_PASSWORD, paste the original CREDENTIALS_KEY, set PORT / PUBLIC_URL
docker compose pull
docker compose up -d
# Copy the backup directory onto this host, then:
./scripts/restore.sh /path/to/portable-backup --confirm

If you cloned the repository instead of curling two files, run the scripts from that checkout after Compose is up.

Required environment variables

  • CREDENTIALS_KEY — must match the old install for encrypted integration credentials.
  • POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB — used by Compose; password can be new if volumes are new.
  • PORT — published HTTP port on the new host.
  • PUBLIC_URL — set when phones should use a public HTTPS origin different from the browser URL.
  • ROLODEX_IMAGE — pin a release close to the backup’s application_version when possible.

Full list: Environment variables.

Hostnames and URLs after migration

  • Point the reverse proxy or Cloudflare tunnel at the new host’s PORT.
  • Open the site once through the new address so Settings can pick up the public origin.
  • Set or update PUBLIC_URL when CardDAV/CalDAV clients must use that origin.
  • Update phone CardDAV/CalDAV account URLs if the hostname changed; client passwords in Rolodex stay the same.

External integrations

Encrypted credentials travel inside the database dump. With the correct CREDENTIALS_KEY they decrypt on the new host. You may still need to allowlist the new IP/hostname at the provider (Immich URL, mailbox, OAuth redirect URIs). Immich photo libraries stay on Immich — only Rolodex links and settings are in the backup.

Minimum PostgreSQL version

Rolodex Compose uses PostgreSQL 16. Restore onto Postgres 16 or newer of the same major when possible. Restoring a dump onto an older major version is rejected by the restore script.
