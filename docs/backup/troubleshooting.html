Recovery troubleshooting

Backup fails or leaves a .partial folder

  • Confirm docker compose ps shows healthy postgres.
  • Confirm the uploads volume exists (docker volume ls | findstr uploads / grep uploads).
  • Remove the incomplete *.partial directory and run ./scripts/backup.sh again.
  • A published stamp directory is only created after success — do not invent missing files by hand.

Verification fails

  • Checksum mismatch — the files were altered or truncated in transit. Re-copy from the source backup.
  • Missing artifact — incomplete folder; use a full stamp from backup.sh.
  • Unsupported format_version — upgrade Rolodex scripts/docs to a release that understands that manifest, or restore with matching tooling.
  • pg_restore / isolated restore error — dump is corrupt; create a new backup from a healthy install.

Restore refuses to run

  • Add --confirm. Without it the script exits without changes.
  • Preflight must pass (checksums, manifest, dump list, archive paths).
  • Target Postgres major must not be older than the backup’s major version.

Database container failed or volume is gone

docker compose up -d postgres
# wait until healthy
docker compose up -d
./scripts/restore.sh backups/STAMP --confirm

If Postgres data is unrecoverable, remove the broken volume only when you have a verified backup, then recreate and restore: 

docker compose down
docker volume rm PROJECT_postgres-data
docker compose up -d
./scripts/restore.sh backups/STAMP --confirm

Replace PROJECT_postgres-data with the name from docker volume ls.

Uploads volume missing

Start Compose once so it creates the uploads volume, then restore. The restore script clears and repopulates that volume from uploads.tar.gz. Database-only downloads from Settings cannot rebuild files.

Integrations broken after restore

People and files may look fine while Immich/mailbox/API credentials fail. Set CREDENTIALS_KEY in .env to the value from the original install, then docker compose up -d again. There is no way to decrypt those rows without the key.

Interrupted restore

If the script stopped after restoring the database but before uploads, the app may start with mismatched files. Do not assume health from a green container alone. Re-run ./scripts/restore.sh … --confirm from a verified backup, or recreate both volumes and restore into a clean Compose project.
